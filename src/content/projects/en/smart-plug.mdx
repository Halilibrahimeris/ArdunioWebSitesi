  - q: The relay never clicks.
    a: >-
      First check that the relay module is powered from 5V; most relay coils
      will not pull in at 3.3V. Then check the transistor: with its flat face
      towards you, the legs read emitter, base, collector from left to right.

    a: >-
      The module's IN input is almost certainly active-LOW and wired without

  - q: The LED strip does not light at all.
    a: >-
      Check the strip's data direction. WS2812 strips have arrows printed on

<Callout lang="en" variant="danger" title="Do not use mains voltage in this project">
Relay modules can switch 230V, but this project is not designed for that. Mains
voltage kills, and doing it safely requires a proper enclosure, fusing and
insulation.

Test the relay only with **a battery-powered lamp, a small DC motor, or a
low-voltage device on its own adapter**. Hearing the relay *click* and seeing
the contact close is the whole of the lesson here.
</Callout>

## The second solution to the 3.3V problem

In project 3 we used a voltage divider to bring a 5V **input** safely into the
board.

Here the problem runs the other way: the board's 3.3V **output** is not enough
to drive a 5V module.

Most relay modules are **active-LOW**: pulling IN down to ground energises the
relay, and holding it near 5V releases it. Since the board can only produce
3.3V on a HIGH, the module decides that is not high enough and the relay never
switches off.

The solution is a **transistor**:

| Board pin | Transistor | Relay IN |
| --- | --- | --- |
| HIGH (3.3V) | conducts | pulled to GND → relay **on** |
| LOW (0V) | off | the module's own resistor pulls it to 5V → relay **off** |

The transistor both translates the level and keeps the board electrically
separated from the relay.

<Callout lang="en" variant="tip" title="One problem, two solutions">
Project 3: a voltage divider (5V → 3.3V, for an **input**).
Project 7: a transistor (3.3V → a 5V load, for an **output**).

Which one you need depends on the direction of the signal. Knowing both lets
you bridge most gaps between the 3.3V and 5V worlds.
</Callout>

<Step n={1} title="Power down and identify the transistor">

Unplug the USB-C cable and disconnect the external adapter.

The 2N2222 has three legs. **With its flat face towards you, left to right:**

1. **Emitter** (E)
2. **Base** (B)
3. **Collector** (C)

<Callout lang="en" variant="warning">
The order varies between manufacturers. If you are unsure, look up the code
printed on the part (2N2222, PN2222) and check its datasheet. A transistor
fitted backwards will not work, though it usually survives.
</Callout>

</Step>

<Step n={2} title="Build the transistor driver">

Make these three connections:

- **D5** → 10kΩ resistor → the transistor's **base**
- The transistor's **emitter** → the board's **GND**
- The transistor's **collector** → the relay module's **IN** input

The 10kΩ resistor limits the current drawn from the board's pin. Without it the
base current is uncontrolled and both the transistor and the pin suffer.

</Step>

<Step n={3} title="Power the relay">

The relay module's power comes from the **external adapter**:

- Relay **VCC** → external 5V (+)
- Relay **GND** → external 5V (−)

<Callout lang="en" variant="danger" title="Nothing works without a shared GND">
You must also connect the external adapter's negative to the board's **GND**
pin.

Without it the two circuits have no common zero. When the board says "3.3V",
the relay has no idea 3.3V relative to what. The signals become meaningless and
the circuit behaves at random.

This is the rule for **every** project that uses an external supply.
</Callout>

</Step>

<Step n={4} title="Wire the LED strip">

WS2812 strips have **arrows** printed on them showing which way the data flows.
Use the three pads at the end where the arrows begin:

- **DIN** (data input) → the board's **D6** pin
- **5V** → the external adapter's (+)
- **GND** → the shared GND

<Callout lang="en" variant="warning" title="3.3V data is borderline — have a fallback ready">
The WS2812B datasheet wants at least 70% of 5V (3.5V) for a "1"; the board's
3.3V is **below** that line. On a short 8-LED stick it usually works anyway,
but it is not guaranteed.

If the strip flickers, shows random colours or stays dark, the fix takes two
minutes: put a **1N4007 diode** in series with the wire going to the strip's
**5V** pad (banded end towards the strip). The diode drops ~0.7V, the strip
runs at 4.3V and now accepts 3.0V as a "1" — 3.3V clears it comfortably.

On long 30-60 LED strips even the diode may not be enough; then you need a
level shifter such as a 74AHCT125.
</Callout>

<Step n={6} title="Bridge runs both ways here">

In every project so far Bridge went one way. Here **both directions** are in use.

**Downwards** (web → board), as in project 6:

```python
Bridge.call("set_relay", 1)
```

**Upwards** (board → web) is the new part. When the timer expires it is the
microcontroller that switches the relay off, and the web interface needs to
know:

```cpp
// in the sketch, when the timer expires
Bridge.notify("relay_changed", 0);
```

```python
# in main.py
Bridge.provide("relay_changed", relay_changed)
```

Without this the timer would switch the relay off while the interface on your
phone kept showing "ON".

<Callout lang="en" variant="tip" title="A single source of truth">
The web interface assumes nothing on its own. Pressing the button does not
change the display immediately — the message goes to the board, the board
changes its state and reports back, and only then does the interface update.

That way two phones used at once both show the real state. This is called a
*single source of truth*.
</Callout>

</Step>

<Step n={7} title="Run it and try it">

Plug the external adapter in first, then the USB-C cable. Press **Run** and open
the web interface.

1. **Press the relay button.** You should hear a distinct click and see the LED
   on the module light up.
2. **Pick a colour.** The strip changes instantly.
3. **Lower the brightness.** At 0 the strip goes dark.
4. **Set a 5-minute timer.** The relay switches on and the interface says
   "Switches off in 5 minutes". If you would rather not wait, change `60000UL`
   in the code to `1000UL` to turn minutes into seconds for testing.
5. **Open it on a second device.** Switch the relay on from one and the other's
   display updates too.

</Step>
